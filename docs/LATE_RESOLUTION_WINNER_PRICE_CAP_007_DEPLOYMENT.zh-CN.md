研究准入要求参考数据、盘口新鲜度、spread和最小深度合格；仅忽略严格模型的`ReversalBoundary`与`NetEvTooLow`，不额外设置p或距离阈值。完整严格模型及原hybrid路径继续独立记录，没有将研究订单改称production。新研究控制组包含所有合格候选，口径不与旧006 rejected主Shadow强行拼接。

两组同一时刻完成确认且请求相同时，共享一次250ms延迟后的真实盘口模拟读取，结果分别计入自己的账本，减少请求先后造成的比较偏差。这不意味着两套真实资金可以同时消耗同一份流动性。若仅一组此时触发，就独立读取该时点盘口。费用、FOK/FAK等订单类型和流动性折扣仍来自配置，实际配置在新journal首行冻结。

读取结果晚于市场结束的模拟不计成交收益：原始结果保留在error诊断中，两组释放模拟预留，该市场不进入完整匹配收益。执行结果缺失时保留未知状态和预留资金，不自动记作no-fill、盈利或亏损。重启恢复历史账本及已尝试市场；确认计数重新开始。同一journal的研究配置变化将拒绝启动，需要新批次。

## 手动部署：只同步四个文件

在服务器停止旧Winner进程后，按相同相对路径覆盖/新增：

1. `target/release/late_resolution_winner_trading`
2. `.env`（本地已设置007结果/日志路径及研究开关；全局价格范围仍为0.96–0.98）
3. `scripts/run_late_resolution_winner_price_cap.sh`
4. `scripts/late_resolution_winner_price_cap_report.py`

无需源代码、cargo或替换其他策略可执行文件。保留006结果和日志。新增计划JSON及本说明用于本地研究归档，不是服务器运行依赖。

在服务器项目根目录检查新二进制：

```bash
bash scripts/run_late_resolution_winner_price_cap.sh check
```

输出应包含`eth-ask-cap-097-v1`、`candidate_eth_max_ask=0.97`和`paper_only=true`。旧可执行文件不支持该命令，启动脚本会阻止它静默忽略新开关。

随后在tmux启动：

```bash
bash scripts/run_late_resolution_winner_price_cap.sh dry-run
```

启动脚本只使用现成release可执行文件，强制dry-run、BTC/ETH、最后60秒、0.96–0.98原始采集范围、两次确认及5 USDC；研究候选的ETH上限由独立策略固定为0.97。启动日志会记录新run、正式前瞻窗口起点和恢复现金。

同批次重启仍运行相同命令；不要删除journal或复制006订单文件进入007。新参数试验使用新的批次名称，示例：`bash scripts/run_late_resolution_winner_price_cap.sh dry-run server-low-latency-008`。
