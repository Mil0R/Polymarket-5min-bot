# Cross-Market Probability Arbitrage 运行分析报告（2026-08-31）

## 结论摘要

当前运行没有发现可执行的跨市场套利，也没有产生 `shadow_opportunity`。这不是
扫描器没有工作，而是所有完整盘口快照在手续费和执行缓冲后仍为负边际：截至最后
事件，5,623 个有净边际的关系评估全部低于准入阈值，最佳净边际约为 `-0.6117%`。

条件式 Maker/Taker 模型虽然反复产生正边际候选，但它假设 Maker 腿 100% 成交后
立即完成 Taker 对冲，未模拟排队成交概率、逆向选择和单腿暴露，因此不能视为真实
套利收益。当前策略适合继续作为只读研究扫描，不适合接入下单器。

## 条件式 Maker/Taker 研究

截至结果文件末尾共记录约 13,123 个条件式候选；最新周期汇总约为 13,074 个。
其条件边际分布为：

| 分位 | 条件边际 |
|---:|---:|
| P10 | 2.7704% |
| P50 | 5.2988% |
| P90 | 12.0300% |
| 最大 | 15.0027% |

对应可见 Maker 队列前方数量：P50 约 61.76 shares，P90 约 100.16 shares，最大
约 2,588.38 shares。

这些候选的成立条件是“Maker 腿完整成交，然后其它腿立即按 ask 对冲”。系统没有
模拟：

- Maker 腿实际成交概率；
- 排队位置变化和撤单延迟；
- Maker 成交后的逆向价格移动；
- 对冲腿在同一时刻仍有足够深度；
- 单腿暴露、部分成交和跨市场非原子执行。

因此条件边际只能用于筛选下一步研究样本，不能计入收益，也不能作为调低主策略
门槛的依据。

## 关系发现与语义风险

### Deadline Implication

当前 143 条关系全部属于 `deadline_implication`，语义状态均为
`template_inferred_requires_rule_review`。这意味着系统只根据同一事件和不同截止
日期推断包含关系，尚未完成逐条人工规则核对；运行记录中 `live_eligible=false`。

### NegRisk

本轮没有生成可交易的 NegRisk 完备集合，主要原因是：

- `some_deployed_markets_not_tradable`：约 439 次约束失败；
- `missing_tradable_neg_risk_other`：约 472 次；
- `partition_leg_limit_exceeded`：约 24 次；
- `fewer_than_two_tradable_markets`：约 8 次；
- 市场被标记 inactive：约 4,037 次；
- 过期约 80 次、closed 约 82 次。

这说明当前 NegRisk 候选池主要受市场可交易性和 `negRiskOther` 完整性限制，不是
价格模型没有找到价差。直接放宽腿数或跳过不可交易子市场会破坏保证支付关系，不能
作为优化方向。

## 数据质量与延迟

最新周期汇总显示：

- REST 平均延迟约 155 ms，最大约 15,917 ms；
- 盘口最大年龄约 17,156 ms，高于配置的 15,000 ms 上限；
- 最大交易所时间戳偏差约 15,168,947 ms（约 4.2 小时）；
- 本地观测时间差最大约 16,669 ms；
- 累计 REST 请求约 149 万，WebSocket 命中约 1,779 次；
- REST 请求没有失败，但数据大部分仍来自 REST 回退。

巨大的交易所时间戳偏差和超过 15 秒的盘口年龄会使跨市场“同时可成交”的判断
不可靠。当前 fail-closed 行为是合理的，不能为了增加机会而放宽时间一致性。

## 可行性判断

1. **纯 Taker 跨市场套利：当前不可行。** 毛价差被手续费完全吃掉，所有净边际
   均为负。
2. **条件 Maker/Taker：有研究价值但尚无可执行证据。** 正边际来自强假设，队列
   深度从几十到数千 shares，真实成交概率未知。
3. **NegRisk 完备集合套利：当前机会池不足。** 大量子市场 inactive、不可交易或
   缺少 `negRiskOther`，不能通过放宽一致性检查解决。
4. **数据质量：需要继续修复/观察。** 盘口年龄和交易所时间戳偏差已经足以影响
   跨市场原子性判断。
5. **当前不值得开发真实下单执行器。** 先完成语义审核、延迟校准和 Maker 成交
   代理研究，才能判断是否存在可兑现套利。

## 下一步建议

### 必须保持

- 保持 `CROSS_MARKET_PROBABILITY_ARBITRAGE_MIN_NET_EDGE=0.01`，不要因 0 次机会
  而降低到负数或 0。
- 保持 `live_eligible=false`；语义审核未完成前不允许任何实盘路径。
- 保持缺失盘口、过期盘口、时间戳严重偏差时 fail-closed。

### 值得优化

- 将报告器改为在存在未结束 Shadow run 时优先分析该 run，避免默认选择旧 scan。
- 将交易所时间戳偏差按单腿和关系分别记录，并区分“数据源时钟异常”和“真实延迟”。
- 对 13,123 个 Maker/Taker 候选增加可见队列衰减、部分成交和对冲滑点模拟，输出
  成交概率加权后的期望 PnL，而不是仅输出条件边际。
- 只对人工确认 `rules_equivalent` 的 deadline 关系做后续研究，先排除模板误判。
- 对 NegRisk 候选增加“至少两个当前可交易子市场 + 可交易 Other + 统一订单簿时间窗”
  的专门统计，避免把不可交易事件占满扫描量。

### 继续运行的条件

可以继续运行 Shadow 24–72 小时，但目标是收集：盘口时间一致性、条件 Maker 成交
概率、部分成交后的对冲成本和语义审核样本；不是等待当前负边际自行变正。

只有在出现真实的 post-fee 正边际，并且经过时间一致性、深度、语义审核和成交概率
加权后仍为正，才值得进入极小额、完全隔离的 canary 研究。当前没有这个证据。
