## 1. 完成情况

本阶段完成了启动自动对账、恢复任务重启接管、用户订单流断线保护、订单数量语义测试和 Dry-run soak 工具。真实账户写操作仍未执行。

当前恢复链路为：

```text
进程启动
  → 重放每个 pair 的最新日志记录
  → 解析双腿订单与恢复上下文
  → 查询 CLOB 累计 size_matched
  → 有资金地址时同步 Data API 真实持仓
  → 重建 owned-order 映射
  → 重建 HedgeMonitor 与活动恢复卖单
  → 订阅旧恢复 token 的公开订单簿
  → 未解决状态全部结束前禁止新实盘开仓
```

## 2. 主要改动

### 2.1 可重建状态日志

`order-state.ndjson` 的记录新增：

- condition ID；
- YES/NO token ID；
- YES/NO order ID；
- 两腿计划数量、价格和累计成交；
- 恢复 token、相反 token 和目标退出数量；
- 入场价、止盈价、止损价；
- 恢复卖单 ID、剩余数量和已记账累计成交。

新增字段均采用可选/兼容读取方式。旧日志没有完整快照时不会被错误推断为安全状态。

状态日志在内存中维护每个 pair 的最新记录，追加成功并落盘后才更新缓存。交易热路径可以常量时间判断是否存在未解决风险，不需要每个行情事件重新读取整个文件。

### 2.2 启动自动对账

认证成功后、启动实时策略前执行对账：

1. 重放未终结 pair；
2. 查询已知双腿订单的最新累计成交量；
3. 若配置资金地址，则同步 Data API 账户持仓；
4. 重新分类订单对；
5. 双腿完整或部分等量成交时写入终态；
6. 不平衡 pair 恢复为退出监控；
7. 缺少上下文或解析失败的旧记录标为不可自动管理。

不可自动管理的记录默认阻止实盘启动；Dry-run 或显式 override 可启动进程用于排查，但只要日志仍有未解决状态，策略层仍禁止新实盘开仓。

### 2.3 恢复任务重启接管

HedgeMonitor 会从日志恢复：

- 原退出 token 和对侧 token；
- 止盈、止损与入场价格；
- 已经挂出的恢复卖单；
- 已记账成交量和剩余卖出量。

恢复 token 即使属于上一市场窗口，也会作为额外公开订单簿订阅加入当前 WebSocket。恢复卖单状态查询不再依赖盘口必须存在：即使订单簿没有 bid，也会先查询活动订单的累计成交与状态。

### 2.4 未解决状态全局开仓闸门

任何 `partially_filled`、`one_sided` 或 `recovering` 最新状态都会关闭新实盘开仓。只有日志进入 `both_filled`、`both_failed` 或 `recovered` 终态后才重新开放。

该闸门覆盖：

- 当前进程新产生的单腿风险；
- 重启恢复的旧 pair；
- 用户流断线期间 HTTP 补拉发现的新增成交；
- 人工 override 后仍未真正解决的旧日志。

### 2.5 用户订单流断线保护

认证用户流断开时：

1. 退出当前窗口行情处理，因此断线期间不会继续开仓；
2. 等待已经启动的交易任务安全结束；
3. 通过 HTTP 查询所有仍未解决的 owned order，补拉累计成交；
4. 采用 1、2、4…30 秒指数退避重连；
5. 连接稳定运行 30 秒后重置退避。

即使是公开订单簿流或窗口切换导致用户流被重建，只要存在未解决 pair，也会在会话结束时执行一次 owned-order 补拉，覆盖订阅切换空档。

### 2.6 订单数量语义固化

新增统一函数明确 CLOB 响应的资产方向：

- BUY：outcome share 成交量取 `taking_amount`；
- SELL：outcome share 成交量取 `making_amount`。

套利买单和恢复卖单均通过该函数换算，并有单元测试防止以后把卖出所得金额误记为卖出的 share。

### 2.7 Dry-run soak 工具

新增：

```bash
./scripts/dry_run_soak.sh 1800
```

脚本强制设置：

- `DRY_RUN=true`；
- 关闭 TUI；
- 纯文本日志；
- 到时发送 INT，再设置强制退出保护。

本次环境不存在 `.env`，因此在线认证冒烟测试被安全跳过，没有伪造“已在线验证”的结果。
