# Binary Complement Arbitrage 5m/15m Dry-run 分析（2026-09-01）

## 结论

本轮 5m 与 15m 均未发现可执行的双腿套利。两组订单文件均为空，PnL 均为 0；没有下单错误、REST Shadow 错误或资金风控拒绝，原因是候选在进入执行前消失或在 REST 复核时只剩单边盘口。

15m 在本轮实时样本中没有体现出历史回测中略高的持续性优势。5m 的 74 个独立 Shadow 信号和 15m 的 29 个独立信号，经全部延迟和金额组合复核后，双腿同时可成交均为 0。

## 没有交易的原因

### 1. 正常深度候选无法完成 100 ms 连续确认

- 5m：28 个正常深度候选，对应运行指标 `stability_pending=28`。
- 15m：16 个正常深度候选，对应 `stability_pending=16`。

没有候选在至少两次独立盘口更新中持续满足条件，因此 `opportunities_admitted=0`。直接把确认时间降为 0 会重新引入异步双边盘口产生的假价差。

### 2. 被准入规则拒绝的候选仍不可执行

5m 的 37 个准入拒绝：

- 临近结束：27，其中 2 个手续费后为正；
- NO 价格低于 0.20：4，其中 1 个手续费后为正；
- YES 价格低于 0.20：6，其中 0 个手续费后为正。

15m 的 9 个准入拒绝：

- 临近结束：4，其中 1 个手续费后为正；
- NO 价格过低：1，正净边际 0；
- YES 价格过低：4，正净边际 0。

新增的 `source=admission_rejected` REST Shadow 已生效，但上述 5m 3 个、15m 1 个正净边际候选在最快复核时仍全部只有单边或无盘口，双腿成交为 0。因此目前不应降低价格下限或临近结束限制。

### 3. 降低深度门槛仍无意义

5m 只有 1 个深度拒绝信号在手续费后为正，REST 后同样无法双腿成交。维持 `MIN_ASK_DEPTH_USDC=2.0` 比下调更合理。

## 盘口流向

- 5m：1,776 个 REST 样本中，1,632 个只剩单边、144 个两边都不可成交、0 个双腿可成交。
- 15m：696 个 REST 样本中，661 个只剩单边、35 个两边都不可成交、0 个双腿可成交。

单边比例分别约为 91.9% 和 95.0%。这与真正套利的特征相反：信号越明显，越可能是一个盘口已经更新、另一个盘口尚未同步造成的瞬时错位。

## WebSocket 状态

- 5m：219 次 SDK 重连/恢复，总计约 2,993 秒，最长约 107 秒。
- 15m：69 次重连/恢复，总计约 224 秒，最长约 22.5 秒。
- 两组策略级 `stream_connect_failures` 和 Shadow REST 错误均为 0。

重连数量大部分与市场窗口轮换相符，但 5m 最长 107 秒的不可用区间仍值得继续观察。它不会解释零成交，因为候选出现时的 REST 双腿复核结果同样为 0。

## 5m 与 15m 判断

- 5m 信号更多，但没有可执行双腿样本。
- 15m 信号更少，且没有表现出更长的 REST 存活期。
- 历史 15m 回测中唯一的延迟后成交样本，本轮约 10 小时实时运行没有复现。
- 当前样本仍较短，尚不能证明机会绝对不存在；但它进一步降低了 15m 能解决执行问题的概率。

## 建议

1. 保持现有门槛，继续分别运行，不调整深度、确认时间、价格下限或临近结束限制。
2. 至少累计 7 天；若两组各累计 100 个手续费后为正的独立信号后，最快 REST 组双腿仍为 0，则停止双 taker 路线。
3. 为避免两个进程的 REST Shadow 互相排队，可在不同服务器或错开时间运行 5m/15m，或增加每策略独立的 API 并发/速率指标。
4. 若继续研发，应优先评估并发双腿/批量接口可行性以及 maker+taker 结构，不应通过放宽风控制造成交。
