## 9. 结论与建议

1. **维持 fail-closed，继续只跑 5m Shadow**。0/100 已结算正式成交，统计上不允许放宽准入。
2. **把本批次冻结为新的校准/开发集**。任何参数修改必须写入新批次目录，只用新数据判断效果；不要用批次 005 反过来调参。
3. **优先修模型校准，而不是放宽阈值**。模型在模型概率 <0.90 的 ETH 市场预测 0.6056、实际 0.9921，Brier 0.1698——这是 0 成交与"收益看起来存在"两个现象的共同来源。必须用时间顺序切分的训练/验证集重做校准，不能用当前选择偏差样本拟合。
4. **把 0.98 档单独处理**：其盈亏平衡胜率 98.14%，本批次实测 97.62% 且亏损集中在此。若不做模型改进，应把该档位的准入收紧或降额。
5. **建立"一次亏损 = 多少笔盈利"的风控指标**：当前为 ~144 笔；这个数字应作为仓位与预算上限的直接输入，而不是只看胜率。
6. **排查 09-16 11:54 的 3 次快速重启**（前两次无评估产出），以及 Shadow 执行器中 `limit_price` 与 `average_price` 不一致的异常记录。
7. **提高 WS 覆盖率**（当前仅 15/335 次评估来自 WS，95.5% 走 REST）：本轮因 WS 盘口陈旧丢弃 37,444 次、REST 回退 135 次；在考虑真实下单前，需要更可靠的盘口来源与更小的盘口年龄。
