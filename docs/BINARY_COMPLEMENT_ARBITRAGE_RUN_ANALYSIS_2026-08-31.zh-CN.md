# Binary Complement Arbitrage 运行分析（2026-08-31）

## 结论

本轮没有成交不是下单模块报错，也不是资金不足，而是没有任何候选通过完整准入和执行复核。当前 5 分钟 BTC/ETH 样本中存在短暂的 WebSocket 价差，但没有观察到可在真实 REST 延迟下同时买入 YES 与 NO、并在手续费后保持正收益的机会。

因此，当前策略不适合直接放宽参数或进入实盘。继续 dry-run 有研究价值，但应优先补全被价格下限和临近到期规则拒绝的候选的 REST Shadow 验证，并修复本地回测仅覆盖 1 个市场的问题。

## 为什么没有交易

### 1. 正净边际只存在于短暂的 WebSocket 视图

483 个独立 Shadow 信号中，45 个通过固定毛边际，40 个通过动态手续费后的净边际。40 个信号的账面净边际为每份 0.003158–0.156435 USDC，平均约 0.022806 USDC。

但是，REST Shadow 的 0 ms 计划延迟并不等于零执行延迟：请求平均约 162.6 ms，返回时信号实际年龄平均约 237.8 ms。在这个最快组里，40 个正净边际信号对应的 160 个金额样本中：

- 双腿可成交：0；
- 仅 YES 可成交：110；
- 仅 NO 可成交：4；
- 两腿均不可成交：46。

延迟增加到 25、50、100、250、500 ms 后，双腿可成交仍然全部为 0。说明这些信号主要是异步盘口更新或极短暂流动性，而不是可执行套利。

### 2. 偶尔双腿可成交的 REST 盘口全部为负期望

全部 11,592 个 REST 测试中只有 10 个金额样本双腿可成交，来自 3 个独立时点。其手续费后可执行边际分别约为：

- -0.026936 USDC/份；
- -0.034944 USDC/份；
- -0.035000 USDC/份。

它们都没有通过信号门槛。取消手续费门槛只会把确定的负期望当作套利。

### 3. 降低深度门槛不会带来有效成交

54 次深度拒绝的弱腿深度仅为 1.00–1.992 USDC，平均约 1.537 USDC，而且没有一次存活 250 ms。这些候选大多是 YES+NO 原始卖价约 0.99 的 1% 表面价差；加入限价保护和动态 taker 手续费后净值为负。将 `MIN_ASK_DEPTH_USDC` 从 2 USDC 下调，只会增加极小额、短寿命和单腿成交风险。

### 4. 价格下限和临近结束规则可能漏掉研究样本，但尚不能直接放开

176 个准入拒绝中，有 22 条在信号时点仍通过动态手续费门槛：15 条因一侧价格低于 0.20 被拒绝（NO 12、YES 3），7 条因距离市场结束不足 2 分钟被拒绝。这是当前唯一值得进一步研究的漏斗，但现有结果没有对这些被拒绝样本执行同样的延迟 REST 双腿复核，无法证明它们可成交。

建议先让这些候选只进入 Shadow，不进入订单执行，再依据其 0/25/50/100/250/500 ms 双腿存活率决定是否调整价格下限或结束时间。

## 延迟与数据链路

- REST 请求延迟：最小 139 ms，平均 161.4 ms，最大 778 ms。
- SDK 市场 WebSocket 有大量重连/恢复计数，且单次最长不可用约 175 秒；日志没有请求错误，但需要区分正常的市场轮换重订阅与异常断线。
- 由于当前最短 REST 复核后的信号年龄已经约 238 ms，任何依赖 100 ms 级错价的 taker-taker 策略都很难在普通公网链路上执行。

## 本地回测交叉验证

最新 5 分钟回测的 38 个场景全部 0 成交，6 个候选均停留在 `signal_confirmation_pending`。但该回测只读取 1 个 BTC 市场、2,194 个快照；即使本地数据库体积很大，这个覆盖范围也不足以代表 31 天 BTC/ETH 数据，因此不能用它独立否定策略。

## 可行性判断

- 当前实现下的 5 分钟 BTC/ETH taker-taker 套利：未发现可执行空间。
- 直接降低手续费、净边际、确认时间或深度门槛：不值得，会显著增加单腿暴露，且不会改善 REST 双腿存活率。
- 继续收集当前配置：可以，但边际信息增量有限；建议先完善 Shadow 分类再运行。
- 直接实盘：不建议。
- 研究价值：仍有，但应定位为“稀有事件探测”，不能预期稳定成交频率。

## 下一步优先级

1. 对 `price_too_low` 与 `near_market_end` 中手续费后为正的候选执行完整 REST Shadow，单独统计双腿存活率和净边际，暂不放开交易。
2. 修复/核查回测市场选择，使 5m BTC、ETH 的全量市场真正进入回测，并报告市场数、日期覆盖与缺失率。
3. 为 WebSocket 重连增加原因分类和按市场切换/异常断线的独立计数，确认是否存在覆盖盲区。
4. 若新增至少 100 个手续费后为正的独立候选后，REST 0 ms 组双腿可成交仍为 0，应停止继续优化该 taker-taker 版本。
5. 若希望继续探索同一概率恒等式，优先研究 maker-maker 或一腿 maker、一腿保护性 taker 的结构，而不是进一步放宽当前双 taker 风控。
