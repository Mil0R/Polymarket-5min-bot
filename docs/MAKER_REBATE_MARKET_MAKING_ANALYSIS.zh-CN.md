# Polymarket 做市 + 流动性激励（Maker Rebate / Inventory Market Making）原理与可行性分析

> 分析日期：2026-08-26　范围：市场做市（MM）+ 平台流动性奖励（Liquidity Rewards）组合策略

---

## 一、策略概述

**核心思想**：在 Polymarket CLOB 上对同一市场双边挂限价单（买 YES / 卖 YES 或等价的买 NO），赚取两层收益：

1. **买卖价差（Spread Capture）**——成交对手价差；
2. **流动性激励（Maker Rebate / Liquidity Rewards）**——平台为达标的双边挂单支付的 USDC 奖励。

同时承担第三层成本：**存货风险（Inventory Risk）** 与 **逆向选择（Adverse Selection）**。策略盈利条件可粗略写成：

```
利润 ≈ 奖励收益 + 价差捕获 × 成交量 − 逆向选择损失 − 存货持有成本 − 执行成本
```

---

## 二、Polymarket 市场结构基础

| 特性 | 内容 | 对做市的意义 |
|---|---|---|
| 合约形态 | 二元结果代币（YES/NO），结算时 YES+NO 赎回 1 USDC | 可通过 Merge/Split 做**无风险对冲**：持 YES+N 锁定 1 USDC |
| 交易费用 | 目前 maker/taker 均 **0 手续费**，链上 gas 由 CLOB operator 承担 | 挂单无显性成本；但也意味着被"狙击"无费用缓冲 |
| 订单簿 | 链下撮合（operator）、链上结算的混合 CLOB | 延迟低但存在 operator 单点/撤单时序风险 |
| 结算 | 二元 winner-take-all，事件驱动跳变到 0/1 | 尾部存货风险极大，临近结算必须强制撤退 |
| 流动性激励 | 类 dYdX 的 Liquidity Rewards：按日发放 USDC 奖励池 | 这是本策略的核心外部收益来源 |

**关键点**：Polymarket 的"rebate"不是传统交易所那种从 taker 手续费里返佣，而是**平台预算的独立激励池**——收益来源更稳定（不依赖成交量），但也随时可能调整或关停。

## 三、做市原理（Inventory Market Making）

### 3.1 报价逻辑

围绕公允价值 `m`（mid / fair value）挂：

```
bid = m − δ_b,   ask = m + δ_a
```

每轮成交期望利润 ≈ 半价差；成交概率随 `δ` 增大而下降。经典框架（Avellaneda–Stoikov 简化）：

- 最优报价偏移应包含**存货偏斜（inventory skew)**：库存偏多时压低 bid、压低 ask，促使库存向中性回归；
- `δ` 下限受 tick size 和奖励要求的 max spread 约束，上限受竞争队列约束。

### 3.2 Polymarket 特有的对冲工具

由于 YES + NO = 1，存在独特的闭环：

```
Split:  1 USDC → 1 YES + 1 NO
Merge:  1 YES + 1 NO → 1 USDC
Buy YES @ p  ≡  Sell NO @ 1−p
```

因此做市商可以：
- 在 YES 簿和 NO 簿上**同时双边报价**（4 个订单），实际净敞口是两个簿流量的差额；
- 净敞口用 Merge/Split 立即中和，把存货风险压缩到接近零（代价是拆分/合并的操作延迟）；
- 对事件驱动型市场（如 crypto 5 分钟盘），可用外部标的（Binance 永续）做**信号对冲**，但这是相关性对冲而非精确对冲。

### 3.3 公允价值 `m` 的确定是策略成败的一半

- 政治/新闻类长期市场：`m` 变化慢，用订单簿 mid + 新闻监控即可；
- 加密短期市场（如本项目交易的 5 分钟 Up/Down）：`m` 由币价决定且每秒漂移，必须引入外部行情做 fair value 引导，否则挂单就是给趋势交易者送钱（详见第六节）。

## 四、流动性激励（Liquidity Rewards）机制

Polymarket 的奖励计分沿用了 dYdX LP Rewards 的设计思想，要点如下：

### 4.1 计分规则（结构性描述）

对每个参与激励的市场，每个时刻对每个挂单计算得分，大致由四个因子相乘：

1. **规模因子 `s`**：挂单深度（shares），随深度**次线性**增长（指数约 0.7~0.8，即 `s^α`），抑制巨额单刷分；
2. **距离因子**：报价距 mid 越近得分越高，达到 max spread 时降为 0（线性衰减）；
3. **双边要求**：**必须同时挂出买、卖两侧**且都在 max spread 内才计分，单边挂单不得分——这是反 Sybil 的核心设计；
4. **价格折扣**：靠近极端价格（≈0 或 ≈1）的挂单被大幅折价，因为它们几乎不提供真实的风险转移。

### 4.2 分配规则

```
个人奖励 ≈ 奖励池 × 个人累计得分 / 全市场累计得分
```

- 通常按日结算、以 USDC 支付；
- 设有**最低份额门槛**（例如需占该市场总得分的某个最小百分比才有资格），进一步压制小资金刷分；
- 不同市场的奖励池差异巨大——热门政治/体育市场池子大但竞争者多（专业做市公司常驻），冷门市场池子小但可能"躺赢"。

### 4.3 对策略的含义

- 奖励本质上是**平台为"真实双边流动性"支付租金**，收益率 ≈ `奖励池 / 全市场得分总量`，可以事前估算；
- 刷分型挂单（贴着 max spread 边缘、最小有效 size 双边挂满全天）是低风险的"收租"模式，但份额门槛决定了它只在**竞争稀薄的市场**有效；
- 一旦有专业 MM 进入同一个市场，分数被摊薄，单位资金收益迅速衰减到无利可图——**这是一个拥挤度敏感的策略**。

## 五、收益模型（量化框架）

对单个市场，日化损益分解：

```
E[PnL] = R(rewards)                        # 激励分成，确定性较高
       + V × E[spread_capture]             # 价差 × 成交量
       − V_informed × E[adverse_selection] # 知情流量造成的损失
       − E[inventory_tail_loss]            # 结算/跳变时的存货损失
       − C_exec                            # 撤补单延迟、滑点
```

经验规律（做市文献共识，Polymarket 同样适用）：

- **价差收入 < 逆向选择损失** 是常态——单纯吃价差在有效率市场上长期亏损；
- 做市能否盈利取决于：**知情流量占比是否足够低**（政治盘 < 体育盘 < 短时加密盘）；
- 因此 Polymarket 上该策略的现实定位是：**以奖励为主、价差为辅、严格控存货**，而不是传统高频做市。

## 六、可行性评估

### 6.1 分市场结论

| 市场类型 | 奖励收益 | 逆向选择 | 可行性 |
|---|---|---|---|
| 长期政治/宏观（数周至数月） | 中高（池子大） | 低，但偶发新闻跳变 | ✅ **最可行**，经典收租场景 |
| 体育赛事（当日） | 中 | 中（赛况实时驱动） | ⚠️ 可行但需赛况暂停逻辑 |
| 加密 5 分钟盘（本项目标的） | 低（池子小/生命周期短） | **极高**（BTC 秒级驱动，结算归零） | ❌ 纯 MM 不可行；只能作为套利策略的对冲执行手段 |

### 6.2 主要风险清单

1. **逆向选择 / 狙击（pick-off）**：零费率环境下，任何人看到外部价格偏离即可免费吃掉你的陈旧报价。5 分钟盘上这是致命的。
2. **存货尾部风险**：二元合约结算 winner-take-all，未对冲存货一次事件可亏光多日奖励。必须有硬性 max inventory + 强制 wind-down。
3. **激励参数变更风险**：奖励池大小、max spread、份额门槛均由平台单方调整，收益模型可能在一周内失效。
4. **拥挤风险**：专业 MM（含平台自己扶持的做市商）进入同一市场后分数摊薄，边际收益快速归零。需要持续监控自身得分份额。
5. **执行/基础设施风险**：CLOB 撤单延迟、operator 故障期间无法撤单、Split/Merge 链上确认延迟导致的敞口窗口。
6. **合规/账户风险**：地区限制、API 限额。

### 6.3 与本仓库现有系统的关系

本仓库已具备的基础设施可直接复用于 MM 模块：

- ✅ CLOB WebSocket 行情 + 订单管理（`src/` 订单状态机）
- ✅ Split/Merge 链上操作（套利腿合并已实现）
- ✅ 风控骨架（仓位上限、wind-down 自动平仓）
- ✅ 多市场发现（可扩展到非 5 分钟市场）

缺口在于：**fair value 引擎（外部行情→目标 mid）、inventory skew 报价器、Rewards 得分模拟器（估算自身份额）、以及针对长期市场的调度**。这些是增量开发，不是重写。

### 6.4 推荐落地路径

1. **阶段一（只读验证，1~2 周）**：抓取目标市场的奖励参数 + 全簿快照，离线回放计算"若我们挂 X 价位能拿到多少分/多少奖励"，筛选奖励/竞争比最优的 3~5 个长期市场。
2. **阶段二（小额实盘）**：固定对称窄幅报价 + 硬性存货上限（如 ≤ 奖励日均收入的 10~20 倍风险敞口），只赚奖励 + 自然价差，跑 2 周统计实际逆向选择成本。
3. **阶段三（加入智能报价）**：引入 inventory skew 和简单信号偏移；逆向选择实测值持续高于阈值的市场自动退出。
4. **明确不做**：在 5 分钟加密盘上做纯双边做市——该场景下正确角色仍是现有的 spread arbitrage / winner-buy，MM 只适合作为其被动执行方式（把市价吃腿改成预挂限价腿，降低 taker 滑点）。

---

## 七、结论

- **原理成立**：Polymarket 的零费率 + 双币对冲结构（Split/Merge）+ 独立激励池，构成了一个比中心化交易所更"干净"的做市环境；奖励是确定性较高的底仓收益。
- **可行但有强前提**：(a) 只做逆向选择低的长期市场；(b) 有硬性存货风控与结算前强制撤退；(c) 持续监控奖励份额与拥挤度；(d) 把激励参数变更当作常态化风险。
- **对本项目**：不建议改造现有 5 分钟套利主线；建议以独立的"长线市场做市模块"复用现有 CLOB/Merge 基建，先跑阶段一的数据验证再投入开发资源。
