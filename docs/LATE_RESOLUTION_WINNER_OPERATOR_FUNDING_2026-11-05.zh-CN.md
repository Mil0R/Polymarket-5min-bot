# Operator模拟入金

本功能仅操作Operator独立PAPER账户，不涉及真实钱包转账。原008冻结对照和候选资金、交易记录保持原样。

## 使用

1. `O`选择Operator。
2. `F`打开模拟入金弹窗。
3. 输入金额，`Enter`确认；`Esc`取消。
4. 等后台持久化成功的`ACK`，再查看顶部可用现金和累计本金。

每次允许0.01～1,000,000.00 USDC，最多两位小数；补入金额而非设置账户余额。每次独立确认都是一笔新入金。单笔交易额度仍由`E`控制，上限仍为100 USDC。

例如原现金30.86787355、累计本金100、交易盈亏−69.13212645，追加500后：现金530.86787355、本金600、累计入金500，交易盈亏仍为−69.13212645。入金后状态保持原样：已经运行的Operator可在条件满足时入场，暂停的Operator仍需`P`确认恢复。

## 数据语义

- 初始本金100保留，后续通过`operator_funded`事件追加，不编辑或重写注册行，不重置旧亏损。
- 每笔事件记录命令ID、当前run、追加金额、修订版本和时间；后台检查账本目标、当前版本、金额范围与命令ID。相同命令重试不会重复加钱；新命令会再次追加。
- 每次确认前版本变化则拒绝旧命令，刷新后重新确认。未收到回执不代表一定未写入，应先查看余额和记录，避免另建命令重复入金。
- 新增现金与累计本金立即生效，不改变暂停状态、单笔上限、待生效额度、入场确认epoch、已有持仓、预留资金或交易净盈亏。
- 状态页显示累计本金、追加模拟入金、可用现金、在途/未知占用和交易盈亏；顶部Operator状态显示现金及本金。历史日期只筛选交易记录，账户资金字段始终为账本最新状态。
- 交易表只列交易，入金明细通过独立报告的`funding_events`查看。已有`by_revision`仍按尝试时版本归属，不将入金计为盈利。

资金守恒：

```text
累计本金 = 100 + 追加模拟入金
权益 = 累计本金 + 已结算交易净盈亏
可用现金 = 权益 - 待结算成交成本 - 执行未知的预留资金
```

报表命令：

```bash
bash scripts/run_late_resolution_winner_price_cap.sh operator-report server-low-latency-008
```

JSON新增`capital`、`deposits`、`equity`、`funding_events`；`total.pnl`仍只代表交易结果。源SHA256与所有原有审计检查保留。

## 兼容与部署

历史v2账本无需迁移，追加旧账本即可。旧软件无法识别新入金事件，因此升级后端、TUI及Operator报告后再入金；产生入金记录后，回滚也必须使用支持该事件的版本，不能删除资金事件来适配旧版本。

需要替换：`target/release/late_resolution_winner_trading`和`scripts/late_resolution_winner_operator_report.py`。原启动脚本和`.env`无需修改。首次升级正常停止并重启后端与TUI；以后每次模拟入金无需重启。部署保留当前运行/暂停状态、额度、余额及历史交易，未自动补入任何金额。
