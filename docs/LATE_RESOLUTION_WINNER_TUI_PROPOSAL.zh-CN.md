# Late Resolution Winner Trading：低开销TUI设计

2026-11-03按用户最新偏好重新设计：采用TUI，尽量减小服务器开销，放弃完整历史行情曲线和历史窗口回放。当前默认选择“盈亏优先”。本文保留设计依据。当前只读TUI已实现，操作及部署见[使用说明](LATE_RESOLUTION_WINNER_TUI_USAGE.zh-CN.md)。交易参数保持，服务器由用户手动部署。

## 设计边界

保留：BTC/ETH策略参考价、当前5分钟窗口摘要、所选日及累计盈亏、按日期查询的交易表、成交详情、策略推进/结算健康状态。

取消：Web页面与HTTP面板服务、完整历史行情存储、K线/缩放/十字光标、跨日行情回放、持续动画和高频重绘。保留原交易与审计journal，不因取消图表删除交易历史。

第一版不新增行情订阅，不引入新的数据库或图形框架，复用现有Ratatui/Crossterm及已采集行情。TWAP是策略当前使用的参考值，不伪称Binance即时现价。已有其他源时可选展示；未订阅的源显示“未订阅”，不会为补齐价格栏而额外连接。

## 运行方式

推荐“后台策略 + 按需只读TUI查看器”。策略继续在tmux运行；需要查看时在另一tmux窗格打开TUI，退出查看器不会停止策略。关闭查看器后无终端绘制工作，也不为界面持续构建历史页面。

状态通过本地IPC获取已有内存快照，只有查看器订阅时按约1Hz推送最新值。采用容量固定、只保留最新状态的通道，慢终端不能积压消息或阻塞交易。不同于Web，这里无需HTTP监听、浏览器资源或每秒写一份状态文件。实际进程和命令名称在实施时确定，本文不将尚未实现的命令当作可运行命令。

若采用同进程TUI的简化实现，也要允许显式无界面运行，并确保显示线程不影响交易；其“关闭后再打开”行为不能假装与独立查看器完全一样。当前优先按独立只读查看器规划。

## 主屏：盈亏优先

目标终端约100×32列行，80×24进入紧凑布局；不足最小可读尺寸时提示放大终端，不继续挤压或隐藏故障提示。中文按终端显示宽度计算列宽，不按字符串字节数截断。

## 板块说明

### 盈亏

BTC、ETH、合计各一行，同时显示所选日已结算PnL、当前策略累计、所选日胜/负数及当前待结算成本。累计区间和结果截止时间固定标注，不假装是所选历史日的余额。查询历史日期时，行情和策略运行状态仍显示最新值，并保留LIVE/最新状态标识。

默认口径沿用现有研究：按入场日归属已结算收益，迟到结算会更新原入场日，并注明结果更新截止。初版只提供这一种口径，不引入多种日期模式增加操作复杂度。累计结果跨run恢复，不能重启清零。

金额主屏保留4位USDC；详情保留原始精度。cost已含交易费，不能再重复扣费。no-fill记未成交，不能按最终方向算胜场；pending/执行未知各自列成本，不计入已结算PnL。0、缺失、尚未终态必须不同显示。

候选、对照、严格Paper和Shadow账本隔离。R只切换查看的研究轨道，不改变实际执行参数或启停策略。原严格Paper仍可能是0成交，不能替代007研究成交统计。

### 当前行情及窗口

用两行数值表代替走势图：策略当前TWAP、相对开窗变化bps、Up/Down ask、剩余时间、确认次数、当前阻断原因。窗口ID与实际参考源可展开查看。币价单位USD，合约价单位USDC/份，避免0.97与BTC/ETH价格混淆。

行情来自交易进程已使用的数据；不为显示另发REST请求，不额外订阅Binance或Chainlink现货流。若现价源已存在可显示为额外一列，并标USDT/USD及来源；否则显示未订阅。TWAP与即时现价不等同。

第一版不显示趋势线。若以后确实需要，可选当前窗口迷你折线：复用已采集TWAP、每资产最多300个内存点、切窗清空、无额外落盘，默认关闭。TUI能够绘制此类小图，只是不把它作为当前低开销版本的必选项。

### 交易表与详情

主表至少保留：执行时间、BTC/ETH及Up/Down、委托限价、含费成交均价、实际投入、状态和净盈亏。宽屏可加信号ask；80列紧凑屏把信号价、数量、费用与市场ID移入详情，时间/资产方向/PnL优先保留。显示条数随终端高度变化，禁止无限滚动日志在内存中累积。

Enter详情页展示：市场5分钟区间、信号ask、委托限价、含费均价、份额、费用（已计成本）、信号/执行/结算时间、剩余秒数、确认过程、模型p及校准状态、signed r、盘口年龄/深度、执行请求及总耗时。

未成交均价显示--，而不是伪造为信号ask。状态区分未成交、已成交待结算、执行未知、执行错误、已结算盈利及亏损。p不是未经说明的真实胜率。筛选观察放在详情或状态页，不与交易尝试混为成交行。

历史交易仍支持按天查询。该功能只依赖现有交易账本，不需要历史币价曲线。初次顺序重放生成按日摘要和可重建的轻量偏移索引；之后增量更新，历史日期按需分页读取。切日期在后台读取，有加载状态，不能每秒重读整份journal或阻塞交易循环。内存只缓存有限页和最近记录，历史列表不无限常驻。

### 运行健康

必须分开呈现进程存活、行情新鲜、策略推进和结算推进。页面刷新及时不代表策略正常。

主屏始终显示最后扫描年龄、参考年龄、待结算数量；故障时改为醒目整行提示，例如：

```text
[异常] 策略21小时未推进 | 正在重试已过期窗口 | 待结算2笔
```

状态页再显示：当前目标窗口与实际窗口差、最后结算检查、最老pending年龄、重启/run信息、断线计数、FD/磁盘及近期错误。重复心跳错误合并为一条及累计次数，避免1238条相同错误挤掉其他事件。前后台独立告警逻辑不能因TUI关闭而停止。

窗口过期重试问题仍需修复，展示告警不是修复。未采集全量REST分布时p99显示未采集，不由均值/最大值推算。

## 快捷键及只读交互

- Tab或1/2/3：总览、交易、状态。
- [ / ]：前一天、后一天；D输入YYYY-MM-DD；T回到今天。
- A循环全部/BTC/ETH；R切换候选/对照，保持资金及统计隔离。
- ↑/↓选择记录，PgUp/PgDn翻页，Enter打开详情，Esc关闭详情/返回主屏。
- Q退出查看器，不停止后台策略。主屏退出前可提示“策略继续运行”，让退出语义明确。

不照搬旧多策略TUI的空格启停、P暂停全部、Y恢复等操作；初版查看器不修改交易状态，不提供实盘开关。停止策略仍采用用户现有的手动流程。

## 降低开销的实现要求

1. 复用现有Ratatui/Crossterm，不增Web栈、图形资源或额外行情连接。
2. 正常1Hz刷新；无变化时只更新必要计时字段，按键立即响应。不使用呼吸、持续闪烁或装饰性动画；按用户后续要求，数字变化可短暂高亮。
3. 当前`src/ui/runner.rs`使用200ms tick，且在持有DashboardState锁时调用terminal.draw。实施时改成短锁复制固定大小快照、释放锁后绘制，不让慢SSH输出长时间占用策略所需状态锁。
4. 看板消费者拿最新快照，队列容量有上限；落后的展示更新可覆盖，不可丢弃权威交易/结算记录。显示线程不承担交易、发现市场或查询结算。
5. 增量维护账本摘要；只在有新事件或切日期时更新相关数据，不每帧重算历史。不为了刷新额外执行同步fsync或反复打开日志文件。
6. 查看器关闭后停止界面刷新和历史查询；后台原交易采样与安全监控按原逻辑运行。不要用“tmux没有attach”自动判断是否有人看，显式启动/退出更可控。
7. 模型p、费用、报价上限、确认、预算等策略参数不因界面更新而变化。

1Hz相对当前200ms约将计划刷新频率从每秒5次降至1次，但这不等于总CPU减少80%，还需量测。独立查看器仍会消耗同机资源，也不能声称零开销。

## 交付与验证

先实现盈亏优先的只读主屏、按日交易查询及推进告警；第一版不做任何曲线。需要时再加状态详情和内存迷你线，避免一开始引入历史行情系统。

实现后验证：与现有Python报告逐笔/按日/累计对账；pending/no-fill/费用语义正确；重启不重置账本；关闭TUI不停止策略；80×24可读；慢终端、切日期、翻页时扫描仍推进；卡旧窗口时不能显示健康；查看器开/关的CPU、内存、磁盘、扫描间隔与执行耗时对比。
