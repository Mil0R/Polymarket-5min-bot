## 为什么机会少

当前 dry run 只评估最后 10 秒。15,110 条 REST 单 token 盘口审计中：7,542 条没有卖盘，7,542 条没有买盘，仅 26 条两侧都有挂单，无两侧皆空；请求与响应 token 全部匹配。REST fallback 是针对不可用 WS 盘口触发，这个比例仅描述回退样本，不代表所有盘口或全天市场。

774 个市场窗口最终状态中，759 个为两结果盘口均不完整，3 个成交，3 个延迟拒绝，3 个缺开盘参考，3 个标的 feed 过期，2 个 REST 回退完成时已越过结算窗口，1 个价格范围不合格。最终状态是最后一次记录，不能理解成每个窗口全程都不可交易。

结算前市场大量单边挂单，当前要求买卖两侧齐全。这解释了机会稀少，但仅降低深度要求或删除盘口完整性门槛不能解决概率模型是否有优势的问题。

## 建议

1. 优先做模型输入审计：记录实测波动率、波动率下限是否生效、参考价时间偏差、无下限诊断概率，并核对参考价与结算口径。3 笔成交执行波动率均为 BTC 下限 0.8，但现有日志不能区分实测值与下限影响。先收集证据，不直接降低下限。
2. 增加 30 秒、60 秒研究组，与 10 秒组使用相同成本模型比较盘口完整性与校准。当前代码限制 dry run checkpoint 为 10 秒，需改代码并隔离批次，不能仅修改目录名或回测 checkpoints 参数。
3. 按模型概率、市场价格、资产和参考价方向分组；特别跟踪 0.05–0.30 的低价结果，避免仅因模型靠近 0.5 就持续产生大额虚拟优势。不要根据这 3 笔亏损直接选出新交易规则。
4. 修正延迟拒绝诊断字段，并在报告中补充机会漏斗、投入收益率和总执行延迟；保留已有完整性校验。
5. 可以保留现有版本作为短期对照，但优先完成以上可解释性优化再开始更长验证。按本批次约 3 笔/21.5 小时的速度，50 笔约需 15 天、100 笔约 30 天；ETH/SOL 当前无成交，无法据此估算每资产达到 50 笔的时间。

结论：工程执行质量有改善，尚无正期望证据。此轮主要待验证的是模型与临近结算盘口的匹配，而非进一步压低 REST 延迟。未修改策略代码或 `.env`。
