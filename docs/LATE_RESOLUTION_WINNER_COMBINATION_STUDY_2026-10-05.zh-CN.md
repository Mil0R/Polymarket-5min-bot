## 3. 固定五个候选

以下阈值从已有风险画像提出，登记后保持固定。`ask` 是执行关联评估的卖方报价；`p` 是该买入方向的原始模型概率；`r` 为 **有方向的 margin / reversal boundary**，直接使用记录中的 `reversal_margin_ratio`。

|ID|保留条件|研究用途|
|---|---|---|
|`probability_070`|p ≥0.70|沿用已有高概率观察组|
|`last_20s`|剩余时间 ≤20 秒|沿用已有末段观察组|
|`exclude_high_price_low_probability`|排除 ask ≥0.97 且 p <0.70|验证报价与概率组合|
|`exclude_joint_risk`|排除 ask ≥0.97、p <0.70、r <0.20 同时成立的交集|检验加入距离比是否减少盈利机会损失|
|`price_tiered_probability_ratio`|ask ≤0.96 时 p ≥0.60 且 r ≥0.10；ask >0.96 时 p ≥0.70 且 r ≥0.20|检验不同报价是否需要不同的概率和距离要求|

另设 `control` 保留现有轨道全部主尝试。每个候选相对于 control 单独评估；各候选重叠，不能把收益相加。

这些历史结果用于提出假设。登记后不根据新增负场移动阈值、增加候选，或选择收益最高的分箱。需要修改时应记录新的研究版本与独立起点，保留本轮完整结果。

### 概率与距离比的解释

- `p=0.70` 尚未校准成真实 70% 的结算胜率；它只是当前模型的一个特征阈值。
- `r=0.20` 表示沿买入方向的距离为完整反转边界的 20%。负值也保留，不能取绝对值。
- p 与 r 共同受 margin、波动率和剩余时间影响，相关性较强。
- 固定的报价三档 × 概率三档 × 距离比三档仅作描述，稀疏分箱不独立算成通过验证的策略。

## 4. 验证所需样本与评审顺序

|指标|最低观察节点|优选|
|---|---:|---:|
|登记后新增已结算 ETH 成交|300|500|
|005 + 006 基线及前瞻 ETH 负场总数|10|15|
|各候选前瞻保留 ETH 成交|100|200|
|各候选有成交的北京时间日期|7|覆盖更多日期及行情|

目前可比 ETH 负场为 5 个，需要继续积累约 5–10 个。达到日历日期但样本不足时继续观察；负场很少时也不为满足数量而制造亏损或放宽服务器参数。

以当前全程约 16 ETH 成交/日、近期约 25–28/日估算，新增 300–500 笔 ETH 成交约需要 11–31 天。速率会变化，负场出现时间无法保证。高概率和最后 20 秒组较稀疏，3–5 周后也可能未积累到 100 笔保留成交，应分别标为证据不足。

复核顺序：

1. 检查冻结输入前缀是否一致，是否发生重启、额度/参数变化、未知模型特征或异常结算记录。
2. 看整体和 ETH/BTC 对照的成交、胜负、成本、收益及每日分布。
3. 同时看各候选**保留组和剔除组**：减少了多少负场，也放弃了多少胜场及净收益；比较前瞻保留收益与原 control 收益。
4. 看保留组样本、跨日期稳定性、亏损大小，以及费用后的成本/份额盈亏平衡与名义 Wilson 95% 下界。
5. 满足样本节点且表现稳定的候选进入进一步研究；其他候选继续采样或记录为未获支持。脚本不自动修改交易参数。

100–200 笔是研究评审节点，不代表能证明盈利。高买入价要求接近全胜的结果；Wilson 下界还依赖独立同分布假设，不能消除日内相关性和多候选选择的影响。

## 6. 数据口径和异常处理

- 每市场选最后一次主 Shadow 执行，排除 `sensitivity_confirmed`；完全相同的重复主执行去重，有冲突的同 ID 记录报错。
- **按执行 evaluation ID 结算**，即使市场最后一个候选方向正确，较早成交仍可能亏损。
- 赢场收益 = 成交份额 − 实际记录成本；负场收益 = −成本；未成交收益为零；待结算成交的成本单独列为敞口，不混入已结算收益。
- 价格与成本采用十进制计算。模型观测缺失或 `StalePrice` 的占位概率归入未知，不擅自填成低概率样本。
- 冻结输入前缀修改、截断、计划校验值变化、非布尔结算或不完整 NDJSON 尾行会报错。输入报错时保留上一次成功报告，修复同步后再分析。
- 旧市场新尝试、登记前同步缺口、新 run 的尝试单独统计。程序重启后，先检查是否保持相同配置及构建，再明确登记后续协议版本；新 run 不会自动混入当前前瞻组。
- Journal 的 run 元数据不能完整证明 `.env` 和所有二进制参数保持一致，服务器参数变更仍需人工记录。本轮保持当前配置继续运行。
- 子集回放只分析已经出现的尝试；跳过某次尝试后是否会产生后续入场、成交率如何变化，需要后续独立验证。
